# 🚀 GitHub Actions: Daily Auto-Update Setup Guide

**Problem:** Manually running scripts to update starred repos analysis = tedious  
**Solution:** GitHub Actions automates this → runs daily, pushes results automatically  
**Result:** Always-fresh analysis, zero manual work  

---

## ✅ What This Does

Every **24 hours** (daily at UTC 00:00):
1. ✓ Fetches all your starred repos from GitHub API
2. ✓ Extracts README summaries & metadata
3. ✓ Generates JSON + Markdown reports
4. ✓ Automatically commits & pushes changes to your repo
5. ✓ Updates timestamp so you always know it's current

---

## 🛠️ Setup (5 minutes)

### Step 1: Create GitHub Actions Workflow File

Create a file in your repo:

```
.github/workflows/auto-update-starred-repos.yml
```

Copy the entire contents from `github-actions-workflow.yml` (provided above) into this file.

### Step 2: Repo Structure (Required)

Your repo should look like this:

```
your-repo/
├── .github/
│   └── workflows/
│       └── auto-update-starred-repos.yml     ← Workflow file (copy here)
├── repos_output.json                         ← Auto-generated (will be created)
├── STARRED_ANALYSIS.md                       ← Auto-generated (will be created)
├── github_analyzer.py                        ← Helper script (will be created by workflow)
├── generate_markdown.py                      ← Helper script (will be created by workflow)
└── README.md
```

### Step 3: Enable GitHub Actions (If Not Already Enabled)

1. Go to your repo → **Settings**
2. **Actions** → **General**
3. Ensure "Actions permissions" is set to **"Allow all actions and reusable workflows"**
4. **Save**

### Step 4: Configure Token Permissions

The workflow uses `${{ secrets.GITHUB_TOKEN }}` (automatically available):

1. Go to **Settings** → **Actions** → **General**
2. Scroll to **"Workflow permissions"**
3. Select: **Read and write permissions** ✓
4. Ensure **"Allow GitHub Actions to create and approve pull requests"** is checked
5. **Save**

### Step 5: Customize the Workflow (Optional)

Edit `.github/workflows/auto-update-starred-repos.yml`:

**Change the schedule:**
```yaml
on:
  schedule:
    - cron: '0 0 * * *'    # Daily at 00:00 UTC
    
# Options:
# '0 0 * * *'      = Every day at midnight
# '0 */6 * * *'    = Every 6 hours
# '0 0 * * MON'    = Every Monday at midnight
# '0 9 * * *'      = Every day at 09:00 UTC
```

**Change the GitHub username:**
```yaml
USERNAME = sys.argv[2] if len(sys.argv) > 2 else "AkashPriyadarshii"
#                                                    ^ Change this
```

**Change the branch (if not using `main` or `master`):**
```yaml
git push origin main    # or "master", "develop", etc.
```

### Step 6: Push to GitHub

```bash
git add .github/workflows/auto-update-starred-repos.yml
git commit -m "🤖 Add daily auto-update workflow for starred repos"
git push origin main    # or your branch name
```

## 🔑 Permissions & Security

### What the Workflow Can Do
- ✅ Read your GitHub stars (via `${{ secrets.GITHUB_TOKEN }}`)
- ✅ Write to your repo (commit & push)
- ✅ Create commits with automated messages

### What It CANNOT Do
- ❌ Access private repos (unless explicitly starred)
- ❌ Modify settings
- ❌ Modify other repos
- ❌ Access your personal access tokens (uses only built-in `GITHUB_TOKEN`)

### Token is Secure Because
- It's auto-generated by GitHub Actions
- It's scoped to **only this repo**
- It expires after the workflow completes
- No token is stored or logged

## 🐛 Troubleshooting

### ❌ Workflow Failed to Run

**Check logs:**
1. **Actions** tab → Click failed run → Expand **"update-starred-analysis"** job
2. Look for red `✗` errors

**Common issues:**

| Error | Solution |
|-------|----------|
| `fatal: Permission denied` | Re-check "Workflow permissions" in Settings → Actions |
| `GitHub token not provided` | Token should auto-inject; check workflow file syntax |
| `fatal: not a git repository` | Workflow has built-in `actions/checkout@v4`; ensure it ran first |
| Rate limit hit | GitHub API rate limit (60 req/hr unauthenticated, 5000 auth). Reduce frequency or add exponential backoff |
| `Python: No module named 'requests'` | Workflow installs it; check step logs for `pip install requests` |

### ❌ Files Not Updating

**Check:**
1. Did the workflow actually run? (Check **Actions** tab)
2. Are there changes to commit? (Workflow only pushes if files differ)
3. Is the branch correct? (Check `git push origin main` matches your default branch)

**Force a test run:**
```bash
# In workflow file, add this line to test without waiting 24h:
on:
  schedule:
    - cron: '0 0 * * *'
  workflow_dispatch:   # ← Allows manual trigger
```

Then use **Actions** → **Run workflow** button.

### ❌ Commit Message Has Errors

**The automated commit message includes:**
```
🤖 Auto-update: GitHub starred repos analysis (YYYY-MM-DD HH:MM UTC)
- Total repos: [N]
- Updated via GitHub Actions
```

If timestamp is wrong, it's likely the workflow ran in a different timezone. Fix:

```yaml
# In workflow file, add:
- name: Set timezone
  run: |
    sudo timedatectl set-timezone UTC
```

## 🚀 Advanced: Customize Further

### Option 1: Add Notifications

Send Slack/Discord message on completion:

```yaml
- name: Notify Slack
  if: success()
  uses: slackapi/slack-github-action@v1
  with:
    webhook-url: ${{ secrets.SLACK_WEBHOOK }}
    payload: |
      {
        "text": "✅ GitHub starred repos analysis updated!",
        "blocks": [
          {
            "type": "section",
            "text": {
              "type": "mrkdwn",
              "text": "*Starred Repos Report Updated*\nTotal: 311 repos\nUpdate time: < 2min"
            }
          }
        ]
      }
```

### Option 2: Upload to External Storage

Push the JSON to S3 or CloudFlare R2:

```yaml
- name: Upload to CloudFlare R2
  run: |
    aws s3 cp repos_output.json s3://your-bucket/starred/repos.json \
      --endpoint-url https://[account-id].r2.cloudflarestorage.com
  env:
    AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY }}
    AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_KEY }}
```

### Option 3: Create GitHub Releases

Auto-create a release with the analysis:

```yaml
- name: Create GitHub Release
  uses: actions/create-release@v1
  with:
    tag_name: starred-${{ env.TODAY }}
    release_name: Starred Repos - ${{ env.TODAY }}
    body_path: STARRED_ANALYSIS.md
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    TODAY: ${{ env.GITHUB_RUN_DATE }}
```

Store JSON files in a `history/` folder to track growth:

```yaml
- name: Archive to history
  run: |
    mkdir -p history
    cp repos_output.json history/repos-$(date +%Y-%m-%d).json
    git add history/
    git commit -m "📊 Archive starred repos snapshot"
```

Then analyze trends:
```bash
# How many new repos each day?
wc -l history/repos-*.json

# Star growth?
grep "total_repos" history/repos-*.json
```

## ❓ FAQ

**Q: Will this count against my API rate limit?**  
A: GitHub Actions uses an authenticated token (5000 req/hr), plus it only runs once daily. For 311 repos, you need ~5 API calls. ✅ Safe.

**Q: Can I run this more frequently (every hour)?**  
A: Yes, change `cron: '0 0 * * *'` to `cron: '0 * * * *'`. But API rate limit hits if you run too frequently. Recommended: daily.

**Q: Does this work for private starred repos?**  
A: Yes, the token has access to your private repos. The JSON will include them (but keep the repo private if sensitive).

**Q: Can I use a personal access token instead of GITHUB_TOKEN?**  
A: Yes, but `GITHUB_TOKEN` is preferred (auto-scoped, auto-rotated, more secure).

**Q: What if I star/unstar a repo after the workflow runs?**  
A: Wait for next scheduled run (24h later) or manually trigger via **Actions** → **Run workflow**.
